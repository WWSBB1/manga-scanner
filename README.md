# 漫画管理 APP

漫画压缩包元数据管理界面。纯 Python 标准库 + HTML,手机浏览器访问,
不需要任何前端框架(之前用 Flet 1.0 试过,Flutter Web 引擎在手机浏览器上起不来)。

## 文件

| 文件 | 作用 |
|---|---|
| `scanner.py` | 核心库: 扫描目录、解析 zip 内元数据、SQLite、多条件查询 |
| `fileops.py` | 核心库: 移动/复制 + 大小校验 + 按字段分目录 |
| `source.py` | 数据源层: 本地磁盘与 WebDAV 远程共用一套接口 |
| `app.py` | HTTP 服务 + 网页界面 |
| `plugin_loader.py` | 插件加载器 |
| `plugins/*.py` | 插件 |
| `test_core.py` | 核心库测试 |
| `tools/remote_smoke.py` | 远程冒烟测试(手动,需联网) |

## 运行

```bash
cd <项目目录>
sh start.sh
# 手机浏览器打开 http://127.0.0.1:8951
# 或局域网: http://<手机IP>:8951
```

`start.sh` 会自己定位到所在目录,放在哪里都能跑。

环境变量: `MANGA_DB`(默认项目目录下的 `manga.db`,和程序放一起)、`MANGA_PORT`(默认 8951)。

命令行直接用核心库(不开界面):

```bash
python3 scanner.py --dir /storage/emulated/0/Download
python3 test_core.py
```

## 页面

## 阅读

「阅读」是首页, 直接按标签挑漫画并逐页看:

- 顶部填漫画所在目录(默认 `/storage/emulated/0/Download`), 只认本地 zip;
  库里不存路径, 文件位置现从目录里找。范围可以选「本次扫描到的」或「全部库」。
- 筛选: 标签和条件合并成同一个输入框。选择字段(标签/作者/社团/原作/角色/分类/语言/标题),
  输入文字立即按「包含」筛选, 不查词表、不等待下拉建议; 回车把当前文字收藏成标签。
  已收藏的标签点一下切换选中/取消, 收藏保存在浏览器本地(localStorage), 不写数据库。
  「+ 高级条件」可加等于/包含/不等于/不包含/为空/不为空等条件, 用「满足全部/任一」组合。
- 缩略图取 zip 里第一张图片, 压成最长边 400px 的 JPEG(约几十 KB),
  存在项目内的 `thumbs.db`(独立 SQLite 表, 以文件名+大小为键)。
  **不落地图片文件**, 不会被系统相册扫到; 文件换了内容(大小变了)会自动重生成。
- 每行可切 2/3/4 本。视图可切「网格 / 按作者 / 按标签 / 按原作 / 按角色 / 按社团 / 按分类 / 按语言」:
  分组视图每行左侧是竖排组名, 右侧横滑缩略图(每组最多 10 本), 最右「展开」看该组全部作品;
  上方筛选条件照常生效, 只决定哪些作品进入分组。
- 点封面进入全屏阅读, 上一页/下一页按钮或左右方向键翻页,
  Esc 返回; 单页图片直接从 zip 流式读取, 不写临时文件。
- 远程 WebDAV 目录支持扫描、分类与阅读。

1. **扫描**: 目录/库路径可改,跑扫描,实时日志,可停止。增量: 上次成功
   且文件名 + size 未变就跳过(不看 mtime —— 本地落盘时间与云端
   ModTime 往往不同; 不看有没有元数据 —— 元数据存在 zip 里, 事后补
   进去会改变 size, 照样会重读)。若内容改写后大小恰巧不变, 用
   「强制重扫」补一次。
   **「扫描子目录」默认不勾** —— 只看填的这一层,子目录里的文件不扫到。
   CLI(`scanner.py --dir`) 仍是递归的,不受这个开关影响。
   目录框里也可以填 WebDAV 远程路径(见「远程 (WebDAV) 目录」),但**本地
   和远程不能混在同一次扫描里** —— 库里以文件名为唯一键,混扫会让同名
   文件的元数据与位置对不上,所以会直接报错要求分两次扫。
2. **浏览**: 字段下拉(先刷新值)或包含文本查询,表格展示,点行看全部字段。
   多值字段显示前两个值加 `[N]` 徽标,点徽标展开看全部值(同一作品不重复成多行)。
   **范围默认「本次扫描到的」** —— 只看最近一次扫描扫到的那些, 而不是
   库里堆着的全部历史。下拉可切到「全部库」。值下拉框也跟着范围走。
   (靠扫描返回的文件名列表判定, 不用 `scanned_at`: 增量跳过的记录
   不会刷新它, 拿它筛不出"本次扫到"。)
3. **分类**: 见下节。
4. **统计**: 总数、有元数据数、平均标签数等概览。下面一排按钮列出所有
   有数据的字段(作者/社团/原作/角色/标签/语言/分类/格式/年份…), 点哪个看哪个
   的分布。**范围默认「本次扫描到的」** —— 概览、字段规模、分布明细、点条下钻
   全都按这一批算, 不掺库里以前扫过的作品; 下拉可切「全部库」。
   (范围靠扫描返回的文件名列表判定, 与浏览页共用同一套口径。)
   每个字段默认只展示 **Top 20**(按作品数), 可以:
   - 「显示更多」每次加 100 条
   - 「全部加载」一次拉完(超过 2000 个值时先确认)
   - 搜索框输入关键字过滤值(防抖 300ms)
   - 切换按数量/按名称排序
   - 长尾会折叠显示成「还有 N 个未显示(共 M 条目)」

   点分布条在统计页内展开该值的作品列表。
   实测全库 4 万作品 / 120 万条目的库上, 2000 个文件的范围内取总览约 0.2 秒,
   切「全部库」约 2 秒。

## 分类整理

四步:

1. **处理哪些文件** — 填源目录 + 递归开关。只处理源目录里**且数据库里有**的
   压缩包;库里没有的直接忽略。
2. **筛选条件** — 可加任意多条,条件间选「并且/或者」。每条 = 字段 + 操作符
   + 值。可用字段: 作者、社团、原作、角色、语言、分类、标签、标题、格式。

   | 操作符 | 含义 |
   |---|---|
   | 等于 / 不等于 | 该字段有任一值等于 / 所有值都不等于它 |
   | 包含 / 不包含 | 同上,但是子串匹配 |
   | 为空 / 不为空 | 该字段有没有值(这两项不用填值) |
   | = / >= / <= | 值框填数字(不用填字段值)。先按该字段分组数作品数,只保留
     达标的那组的所有作品。例: `作者 >= 5` = 作品数不少于 5 个的作者的全部作品,
     `作者 = 3` = 正好有 3 个作品的作者。下拉里标了「(作品数)」和上面的
     「等于」(比字段值)区分 |

   字段值按逗号拆开,所以「标签」这类多值字段是按**单个标签**匹配的,
   不是把 `"halo, sole male"` 当成一整串。`标签 等于 halo` 能精确命中,
   `标签 等于 halo2` 不会误命中(旧版用 LIKE 会)。

   更重要的是:**筛选的粒度是「值」不是「作品」**。一个作品有 3 个角色,
   `角色 不包含 alice` 只会把 alice 这个值排除,同作品的 bob/carol 照常参与
   筛选和分类。筛选剩下的值直接决定分类目录 —— 条件写 `角色 包含 alice`,
   该作品就只进 `alice/` 一个目录。

   同一字段的多个条件各自在原始值集合上算,再按 并且/或者 合并,所以条件
   之间没有顺序依赖。

   例外:`为空` / `不为空` 是作品级的(一个作品在某字段上要么有值要么没有),
   不存在「部分有值」。

3. **目标位置** — 基础目录(默认跟源目录相同)+ 「按字段建子目录」(必选)
   + 「多包一层字段名文件夹」(默认勾选)。可选字段: 作者、原作、社团、
   语言、角色、标签、分类、格式。

   | 开关 | 结果 |
   |---|---|
   | 勾选(默认) | `Download/作者/zmix/xxx.zip`、`Download/标签/lolicon/xxx.zip` |
   | 不勾 | `Download/zmix/xxx.zip` |

   勾上时不同分类维度各占一个文件夹(作者/、标签/、角色/…),不会混在一起。
   取不到值的放 `未分类/`。页面底部会实时显示当前设置会生成什么路径。

   **多值字段会扇出**: 一个作品有多个作者(或角色、标签),就每个值目录
   各放一份。例: 作品 X 的作者是 `alice, bob`,按作者分类会得到
   `alice/X.zip` 和 `bob/X.zip` 两份。移动模式下两个副本都生成后才删源文件,
   副本没做全会保留源文件并报错。单个字段最多扇出 12 个目录。

4. **执行** — 复制或移动(**默认移动**)。勾了「先预览」(默认)会先显示
   **文件 → 目标路径** 对照表(扇出的会标「共 N 份」),确认后才真正动文件。
   移动前还会再弹一次确认,说明会生成几份、不可撤销。

**目标已存在同名文件时跳过**(不改名、不覆盖)。所以同一个分类操作重复执行
多少次,结果都一样,不会堆出 `xxx (1).zip` `xxx (2).zip` 一堆副本。
移动模式下跳过的文件也不会删源。界面会显示「N 已存在被跳过」。

移动会校验目标大小一致才删源。库不记路径,所以**源目录必填** ——
文件在哪由它当场扫出来,用完即弃(见下面「数据库」)。

## 远程 (WebDAV) 目录

扫描、分类整理和阅读都支持 WebDAV 远程路径, 写法是 `remote:路径`,
例如 `123:/本图/本子zip`。凭据放在项目目录 `.env` 的 `WEBDAV_URL/WEBDAV_USER/WEBDAV_PASS`。

| 操作 | 本地 | 远程 |
|---|---|---|
| 扫描 | ✔ | ✔ 只读元数据, 不下载整个压缩包 |
| 移动 | ✔ | ✔ 服务端移动, 不重新上传 |
| 复制 | ✔ | ✘ 不支持(见下) |

几个必须知道的点:

- **远程不能复制**。123 云盘的 WebDAV 对 COPY 返回 500, 调用只会白等,
  所以远程模式下「复制」会被直接拒绝并说明原因。请用移动。
- **多值扇出只搬第一个目录**。一个作品有多个作者时, 本地会给每个作者
  各放一份; 远程做不到复制, 所以只移到第一个目标, 其余目录会在日志里
  列出来(不会假装成功)。
- **目标已存在时跳过, 不覆盖**。与本地口径一致 —— 远程移动前会先查目标,
  同大小就跳过, 大小不同则报冲突并保留原文件。
- **源和目标必须同类**: 都是本地或都是远程。跨存储(本地↔远程)需要下载
  再上传, 暂不支持, 会直接报错。
- 远程扫描默认串行。123 网盘在连续读一批文件后会限流(直接返回空内容),
  并发越高越容易触发。触发时会自动重试, 仍失败则按「限流」报错并提示
  稍后重扫 —— 不会伪装成"文件损坏"。
- 远程解析进度在扫描日志里, 大目录列清单本身可能要几十秒。

冒烟测试(需要联网, 会做一次移动往返并清理临时文件):

```bash
python3 tools/remote_smoke.py "123:/本图/图包压缩包"
```

## 写插件

往 `plugins/` 塞个 .py:

```python
NAME = "我的功能"
def build(app):
    # app.current_db() / app.run_bg(fn) / app.sync(fn)
    return "html 字符串"
```

重启 `python3 app.py` 即生效。**无需编译打包。**
(注: 插件系统目前还是 Flet 时代的接口,纯 HTML 版用的是内置统计页,
要加新页面直接改 `app.py` 里的 HTML 和 API 更快。)

## 支持的元数据格式

zip 内: `ComicInfo.xml` / `info.json` / `meta.json` / `metadata.json`。
归一化优先级 info > meta > metadata > xml。
原文全部存库(archives 表四个原文列),归一化字段在 meta 表,
ComicInfo 其余标签存 `other_fields` JSON 列。
rar/7z 只统计不解析。

**占位值当空**(见 `PLACEHOLDERS` / `FIELD_BLANK_VALUES`):
- 任意字段的 `Unknown` / `N/A` / `None` / `Null` —— 下载器填的"未知",不是真实取值。
- **原作字段的 `original`** —— 原创作品(非同人),对"原作"维度就等于没有原作,
  按原作分类时落到「未分类」,而不是单独占一个 original 目录。
  只精确匹配整值: `last origin`(手游 Last Origin)是真实作品,不受影响。

## 数据库

`archives(name 唯一键, size, mtime, 原文×4, extra_json, has_meta, error...)`

**库里不存路径。** 路径会变(文件挪窝、外接盘换挂载点),存进去只会过期。
位置在需要时现取:扫描时记在内存里(`scan_dirs` 返回的 `paths`),或分类前
用源目录扫一遍(`fileops.match_in_db`),搬移完就不再关心。
增量判断只比 `name` + `size`,`mtime` 仅作记录不参与判断: 本地落盘
时间和云端 ModTime 可能完全不同。文件换位置后重扫既不会误判成
"新文件",也不会被当成"同名冲突"跳过。
`meta_values(archive_id, field, value)` — 各字段按逗号拆分后的索引表,
筛选/计数/分组都基于它。`meta` 表仍保留原始字符串供详情页显示。
`meta(archive_id 主键, title, artist, group_name, parody, character, tags,
language, category, page_count, source_url, source_gid, year/month/day,
translated, format, other_fields)`
